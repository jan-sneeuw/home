This was a pretty fun box. Even though I needed some hints, and still took a long time to finish the box, I feel that I learned a ton.

The CTF starts by enumerating a Wordpress instance, finding an SSRF vulnerability that leads to an unauthenticated local file-read. Using this, we find some credentials for web-access. Once we're logged into the web-app, we find that a custom plugin is installed, which contains a backdoor for a web-shell, which we use to catch a reverse shell as the first local user in a long chain of local user-accounts through which we pivot using standard tricks, such as access misconfigurations, exposed SSH-keys, and old backup-files.

Next, I went down a rabbit hole trying to exploit `xmlrpc.php`.

> `xmlrpc.php` lets external apps talk to a site by sending XML-formatted requests (using the XML-RPC protocol) over HTTP, for things like publishing posts, editing content, or managing comments without logging into the admin dashboard. It receives XML commands and simply executes them.

After some googling, it seemed as though this was the intended path, since I found various repos containing exploits, such as [this one](https://github.com/rm-onata/xmlrpc-attack), and moreover this endpoint actually responded, saying it wants a POST request:

The second vulnerability sounded easier to verify (with RCE in mind), so I left the XSS for later, in case the SSRF would turn out to be a dead-end.

## Lessons Learned

1. If the target is Wordpress, always launch a `WPScan` scan (with API-key!) in the background for enumeration---it **never** hurts.
2. Even if you find a clear backdoor in the source code, it may not be easy finding the access point (i.e. finding `/wp-admin/index.php?cmd=id`)
3. If you find a DB, **always** try to dump it and crack hashes etc.
4. Give the process of cracking hashes more time (or try `john` instead of `hashcat`). Otherwise you may miss things.
5. Sometimes, `linpeas.sh` is useless. I ran LinPEAS twice in this CTF, and in both instances it turned out to be totally unnecessary.
6. For local PrivEsc and pivoting, always try the easy things first: `sudo -l`, `su USER`, find `.ssh` directories, check `env`, look for files that are out-of-place, ...
7. `zip2john` is a very useful tool (in fact, any `XYZ2john` binary is useful, and I should always think of using this tool if I need to crack some password)
8. It's very easy to fall down a rabbit-hole, i.e. first trying to exploit `xmlrpc.php`, just because it came up on scans.
