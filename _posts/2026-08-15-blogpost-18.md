## Introduction

I recently realized that I didn't really understand port-forwarding. Sure, I understood that we "connect" one port to another using some service, but I hadn't really seen any examples of this. It turns out that for ethical hacking and CTFs, knowing how to forward ports is an incredibly useful skill. So I just sat down and read some blogposts and did some googling. Here's what I found:


## A Practical Example

Following one of Ippsec's HTB walkthroughs (don't remember which one), we had the following scenario:

1. We had performed initial access to a server and had SSH'ed onto the box as user `enzo`
2. On the box, there was a web-app running on port 8000, i.e. on `127.0.0.1:8000`, which one finds by running `ss -tuln`

- **Problem**: We don't have a `tty` on the target machine (only a shell), so we can't view the content of the web-page clearly (could use `curl`, but it'd be a pain)
- **Solution**: Forward port 8000 back to our attacker machine, so we can actually view the web-page.

## Explaining the Details

So what happens in the image? 

1. First, make sure that you're working in an active SSH session, otherwise it won't work!
2. Press `ENTER` and type `~C`. This will enter the SSH escape command line `ssh>`
3. Now forward the port, i.e. `-L 8001:127.0.0.1:8000`, which says "establish a local connection through the SSH tunnel between the attacker endpoint `127.0.0.1:8001` and target endpoint `127.0.0.1:8000`"
4. Now we can view the web-page on our attacker machine

Here are a few important notes:

1. We only entered the `ssh>` command line because we were mid-session. Running at connection time, we would have entered `ssh -L 8001:127.0.0.1:8000 user@target`
2. I was originally confused by the syntax, but the "`127.0.0.1:8000`" refers to the target localhost, whereas the localhost for the attacker is simply omitted, so we only write `8001` (or any other port we like)
3. The general syntax is `-L [bind_address:]local_port:remote_host:remote_port`
4. We really made important use of the SSH-tunnel here: We used the fact that we already had an established, trusted (!), connection between the attacker and target machines! Otherwise, we could simply forward totally at random and with no security.
